# Chamber Brief Bank – Product Requirement Document (PRD)
_Last updated: October 2026 – v0.1.0_

## 1. Vision
Empower law chamber counsels to instantly search, access, and reference verified court briefs and legal documents from any device, while providing the Director of Litigation with full administrative oversight.

## 2. Problem Statement
Chamber legal briefs are currently decentralized across personal laptops and physical archives, making precedent research slow and disorganized. Without a role-managed repository, counsels lose billable hours searching for past arguments, and administrative oversight is lost.

## 3. Goals & Success Metrics
| Goal | KPI | Target |
| :--- | :--- | :--- |
| Speed up precedent retrieval | Average brief search time | ≤ 10 seconds |
| Centralize litigation assets | Briefs indexed in bank | 100% of active chamber filings |
| Secure access control | Unauthorized access attempts | 0 security breaches |

## 4. Personas & User Stories
- **Persona 1 – Director of Litigation (Admin):** Manages advocacy strategies, reviews briefs, and controls repository access.
  - **US-1:** *As a* Director of Litigation, *I want* to upload new PDF briefs and tag them by suit number/topic, *so that* the chamber bank stays updated.
- **Persona 2 – Chamber Counsel (User):** Needs quick, mobile-friendly access to legal precedents during court preparation.
  - **US-2:** *As a* Counsel, *I want* to search legal briefs by keyword or court level, *so that* I can cite relevant precedents quickly.

## 5. Scope & MVP Roadmap
### 5.1 MVP (v1.0) [MVP]
- [MVP] Public landing/hero view with global search bar interface.
- [MVP] Supabase User Authentication (Counsel vs. Director permissions).
- [MVP] PDF document upload & storage bucket integration.
- [MVP] Brief indexing table with search filtering (Suit No, Court, Area of Law).

### 5.2 Phase 2 (v1.1)
- Full-text document search inside uploaded PDF files.
- Brief citation exporter (Auto-generate legal citations).

## 6. Architecture & Tech Stack
- **Frontend:** Vite + React + CSS (Mobile-responsive design)
- **Backend & Database:** Supabase PostgreSQL (Document metadata & role management)
- **Storage:** Supabase Storage Buckets (Encrypted PDF document blobs)
- **Auth:** Supabase Auth (Email/Password with Row-Level Security)

## 7. High-Level Code Contracts
// ==========================================
// 1. DATABASE MODELS (Supabase Tables)
// ==========================================

/**
 * Represents a single legal brief entry stored in PostgreSQL database.
 */
export interface LegalBrief {
  id: string; // UUID primary key generated by Supabase
  title: string; // e.g., "State v. Okon & Ors"
  suit_number: string; // e.g., "FHC/L/CS/2026/104"
  court_level: 'Supreme Court' | 'Court of Appeal' | 'High Court' | 'Magistrate Court';
  area_of_law: string; // e.g., "Constitutional Law", "Criminal Procedure", "Contract"
  summary: string; // Key ratio, facts, or legal arguments summarized
  file_url: string; // Public or signed URL linking to PDF stored in Supabase Storage
  file_path: string; // Internal storage path inside the 'briefs' bucket
  uploaded_by: string; // User UUID from auth.users (Director of Litigation)
  created_at: string; // ISO 8601 Timestamp (e.g., "2026-10-27T01:30:00Z")
  updated_at?: string;
}

/**
 * User profile metadata extending Supabase Auth accounts.
 */
export interface UserProfile {
  id: string; // UUID matching auth.users id
  full_name: string; // e.g., "Director of Litigation" or "Counsel Alex"
  email: string;
  role: 'director' | 'counsel'; // Controls permissions (Admin vs Read-Only)
  chamber_title?: string;
  created_at: string;
}

// ==========================================
// 2. FORM & PAYLOAD INPUT CONTRACTS
// ==========================================

/**
 * Payload sent when uploading a new brief (Director of Litigation only).
 */
export interface UploadBriefPayload {
  title: string;
  suit_number: string;
  court_level: LegalBrief['court_level'];
  area_of_law: string;
  summary: string;
  pdfFile: File; // The binary PDF file selected from mobile or desktop
}

/**
 * Filter parameters for searching legal briefs in real-time.
 */
export interface BriefSearchFilters {
  query?: string; // Text string matching title, suit number, or keywords
  court_level?: LegalBrief['court_level'] | 'All';
  area_of_law?: string | 'All';
}

// ==========================================
// 3. API RESPONSE CONTRACTS
// ==========================================

export interface APIResponse<T> {
  data: T | null;
  error: string | null;
  status: number;
}
## 8. Non-Functional Requirements (NFRs)
- **Mobile Usability:** Responsive viewport design optimized for smartphones (`npm run dev -- --host`).
- **Security:** Row Level Security (RLS) policies in Supabase to restrict document uploads exclusively to the Director of Litigation role.
- **Performance:** Initial UI load time ≤ 1.5s on local dev.
